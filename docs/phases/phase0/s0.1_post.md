## 4. Decisions Made

### Decision 1: Android-only target framework for WorkGrid.App
**Context:** The default MAUI template multi-targets `net8.0-android;net8.0-ios;net8.0-maccatalyst;net8.0-windows10.0.19041.0`. Our dev machine is Windows with no iOS/macOS tooling. The brief specifies Android as the initial mobile target.
**Decision:** Set `<TargetFrameworks>net8.0-android</TargetFrameworks>` in `WorkGrid.App.csproj`.
**Trade-off:** Windows MAUI target was dropped from the csproj. If Windows desktop testing is needed later, it can be re-added. iOS/macOS targets were never viable on this machine.

### Decision 2: Cleaned ASP.NET Core boilerplate
**Context:** The `dotnet new webapi` template generates a `WeatherForecast` sample endpoint and model.
**Decision:** Removed `WeatherForecast.cs` and `WeatherForecastController.cs`. Replaced `Program.cs` with a minimal clean baseline (Swagger + HTTPS redirection only).
**Rationale:** Per Section 21 — no API endpoints in S0.1.

### Decision 3: No `Directory.Packages.props` yet
**Context:** Section 14 suggests central package management. However, no meaningful NuGet dependencies have been introduced yet (no EF Core, no SQLite, no MediatR).
**Decision:** Deferred `Directory.Packages.props` until S1.2 when real package dependencies arrive.
**Rationale:** Adding an empty or speculative CPM file would be premature.

## 5. Known Issues & Warnings

### Warning: CA1805 in MAUI template code
`MainPage.xaml.cs` line 5 initializes `int count = 0` explicitly. This is generated by the MAUI template and is harmless. Will be cleaned up when we replace the default MAUI UI in S1.x.

### Warning: JAVAC source/target 8 obsolete
Android build emits warnings about Java source/target level 8 being obsolete under JDK 21. This is a .NET Android SDK toolchain issue, not a project issue. No action needed — it compiles fine.

### Note: MAUI Windows target still builds
Despite changing `TargetFrameworks` to `net8.0-android`, the build output shows a `net8.0-windows10.0.19041.0` build artifact. This appears to be a cached/implicit MAUI behavior. Not blocking, but worth investigating in S0.2 if it causes confusion.
