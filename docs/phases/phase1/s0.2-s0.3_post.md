## 2. What S0.3 Actually Did

### Domain Entities (S0.3.2 – S0.3.4)

**`Employee.cs`**
- Properties: `Id` (Guid), `EmployeeCode`, `Name`, `Email`, `Department` (nullable)
- Invariants enforced in constructor:
  - ID cannot be `Guid.Empty`
  - EmployeeCode cannot be null/whitespace
  - Name cannot be null/whitespace
  - Email must contain `@`
- Has `UpdateDetails()` method with same validation
- No salary, no Aadhaar, no address, no HR bloat. This is an asset management system, not an HR platform.

**`Asset.cs`**
- Properties: `Id`, `AssetTag`, `Name`, `AssetType` (nullable), `SerialNumber` (nullable), `Status`
- `AssetTag` is auto-uppercased on construction
- State transition methods: `MarkAssigned()`, `MarkAvailable()`, `MarkMaintenance()`, `Retire()`
- Invariant: Once `Retired`, an asset cannot transition back to any active state

**`Assignment.cs`**
- Properties: `Id`, `EmployeeId`, `AssetId`, `AssignedAt` (DateTimeOffset), `ReturnedAt` (nullable), `Status`
- Invariants:
  - Both `EmployeeId` and `AssetId` must be non-empty Guids
  - `ReturnedAt` cannot precede `AssignedAt`
- `CompleteReturn(DateTimeOffset)` method sets return date and flips status to `Returned`

### Enums (S0.3.5)
- `AssetStatus`: `Available`, `Assigned`, `Maintenance`, `Retired`
- `AssignmentStatus`: `Active`, `Returned`

### Exceptions
- `DomainValidationException` — thrown when any domain invariant is violated. Inherits from `Exception`. Intentionally simple.

### Domain Tests (S0.3.7)
23 tests across 3 test classes:

All tests use xUnit. No mocking framework needed because the domain is pure C# with no external dependencies.

## 4. Known Issues & Tech Debt

### CA1707 Warnings in Test Project
The test methods use underscore naming (`Constructor_WithValidData_CreatesEmployee`) which triggers `CA1707`. This is a **deliberate** test naming convention (Method_Scenario_ExpectedResult). The warnings are noisy but the convention is readable.

**Recommendation for Phase 1:** Either suppress CA1707 in the test project's `.csproj` or `Directory.Build.props`, or switch to a different naming convention. Not urgent.

### LF/CRLF Git Warnings
PowerShell's `Set-Content` writes LF line endings, but the repo uses CRLF (Windows). Git warns about this on every commit. Not a functional issue but noisy.

**Recommendation:** Ensure `.gitattributes` is configured with `* text=auto` or explicitly set `*.cs text eol=crlf`. Low priority.

### MainPage is Minimal
The current `MainPage` is a single screen with a title, status label, and a button that increments a counter. It exists purely to prove MVVM wiring works. Phase 1 will replace it with real screens.

## 7. What Phase 1 Needs to Do

The foundation is ready. Phase 1 (S1.1+) should focus on:

1. **Add EF Core + SQLite** to `WorkGrid.Infrastructure` — create `WorkGridDbContext`, configure entity mappings for `Employee`, `Asset`, `Assignment`
2. **Define repository interfaces** in `WorkGrid.Domain/Contracts/` (e.g., `IEmployeeRepository`)
3. **Implement repositories** in `WorkGrid.Infrastructure/Repositories/`
4. **Build real MAUI screens** — Employee list, Asset list, Assignment flow
5. **Wire up navigation** — likely `AppShell` with tab-based or flyout navigation
6. **Add application services** in `WorkGrid.App/Services/` to coordinate domain operations

The domain model is stable enough to build against. The entity shapes may evolve slightly (e.g., adding `Department` as a proper entity instead of a string), but the core `Employee → Assignment → Asset` relationship is solid.
