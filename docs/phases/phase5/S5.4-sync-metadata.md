# S5.4 — Sync Metadata & Change Capture

## Objective
Make the synchronization model persistent and operational.

## Approach
**Option B: EF Core SaveChanges Interception**
- \WorkGridDbContext.SaveChangesAsync\ and \SaveChanges\ overridden to inspect ChangeTracker
- Syncable types: Employee, Asset, Assignment
- Operations captured: Create, Update, Delete (tombstone)
- Atomicity guaranteed: domain mutation + sync record committed in single SQLite transaction

## Schema Changes
- \SyncDevices\ — stable device identity (1 row per database)
- \SyncChanges\ — change log with payload, hash, sequence
- \SyncCheckpoints\ — last applied sequence per remote replica

## Key Decisions
- No repository modifications required
- No domain entity modifications required
- No base entity class introduced
- Device identity auto-created on first mutation
- Sequence numbers: monotonically increasing per device via MAX query
