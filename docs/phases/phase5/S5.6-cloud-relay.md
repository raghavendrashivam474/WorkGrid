# S5.6 — Cloud Relay Foundation

## Objective
Introduce first real synchronization transport: Cloud Relay (Path B).

## Architecture
- \/api/sync/*\ endpoints (separate from CRUD API)
- \RelayCoordinator\ — ephemeral in-memory message router
- \ISyncTransport\ — client-side transport abstraction
- \HttpSyncRelayTransport\ — HTTP implementation

## Protocol Flow
1. POST /api/sync/session — register device session
2. POST /api/sync/manifest — upload local manifest
3. GET /api/sync/manifest/{id} — pull remote manifest
4. POST /api/sync/envelope — push changes to relay
5. GET /api/sync/pending/{id} — poll incoming changes
6. POST /api/sync/ack — acknowledge receipt

## Key Decisions
- Relay is NOT authoritative database
- Relay is NOT domain-rule engine
- Existing JWT auth reused
- \SyncObjectKeyJsonConverter\ for dictionary wire serialization
- Envelope deduplication by ID
